# تست‌های E2E

این تست‌ها روی **بک‌اند و دیتابیس واقعی** اجرا می‌شوند، نه ماک. هر تست داده خودش را با پسوند یکتا می‌سازد، پس روی یک دیتابیس چند بار پشت سر هم هم اجرا می‌شوند.

## اجرای محلی

```bash
# ۱. SQL Server و Redis
docker run -d --name erp-sql -e ACCEPT_EULA=Y -e 'MSSQL_SA_PASSWORD=E2e_Passw0rd!' -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest
docker run -d --name erp-redis -p 6379:6379 redis:7-alpine

# ۲. API (در شروع migration می‌زند و کاربر admin را می‌سازد)
cd ERPDotNet
ASPNETCORE_ENVIRONMENT=Development ASPNETCORE_URLS=http://localhost:5000 \
ConnectionStrings__DefaultConnection='Server=localhost,1433;Database=ERP_E2E;User Id=sa;Password=E2e_Passw0rd!;TrustServerCertificate=True;' \
ConnectionStrings__Redis=localhost:6379 dotnet run --project ERPDotNet.API

# ۳. فرانت و تست‌ها
cd erp-frontend
NEXT_PUBLIC_API_URL=http://localhost:5000 npm run build && npx next start -p 3000 &
npx playwright install chromium   # فقط بار اول
npm run e2e
```

`E2E_BASE_URL` و `E2E_API_URL` آدرس فرانت و API را عوض می‌کنند.

## سناریوها

| فایل | چه چیزی را می‌سنجد |
|---|---|
| `auth.spec.ts` | ورود موفق و ناموفق، برگشت به صفحه ورود بدون توکن |
| `stock-counts.spec.ts` | شروع انبارگردانی از موجودی فعلی، جلوگیری از نهایی کردن با سطر شمرده‌نشده، افزودن کالای پیداشده، نهایی کردن با سند اضافی و کسری پیش‌نویس، اثر قطعی شدن آن‌ها روی موجودی، رد نهایی کردن دوباره |
| `units.spec.ts` | خطای اعتبارسنجی، ذخیره ضریب تبدیل و دقت اعشار واحد فرعی، هشدار تغییرات ذخیره‌نشده |
| `products.spec.ts` | تعریف کالا با لوک‌آپ واحد، خطای کد تکراری |
| `inventory.spec.ts` | ثبت رسید از فرم، قطعی شدن و نمایش در گزارش موجودی |
| `inventory-docs.spec.ts` | سند انتقال با قفسه مقصد و جابه‌جایی موجودی، ویرایش سند پیش‌نویس، فقط‌خواندنی بودن سند قطعی، بازیابی پیش‌نویس بعد از رفرش |
| `boms.spec.ts` | ثبت BOM با چند ماده اولیه (یک بار هم با سرور کند)، رد شدن BOM چرخه‌ای، کالای جایگزین، ویرایش BOM |
| `bom-outputs.spec.ts` | مقدار پایه BOM، محصول همزاد با سهم بها و محصول فرعی از فرم (ثبت و ویرایش)، رد سهم بهای ۱۰۰٪ همزاد، محاسبه درخت محصول به نسبت مقدار پایه |
| `fefo.spec.ts` | پیشنهاد بچ و قفسه به روش FEFO در حواله: زودترین انقضا اول، شکستن سطر بین بچ‌ها، کنار گذاشتن بچ منقضی، ثبت و قطعی کردن با همان تخصیص و گزارش کسری |
| `organization.spec.ts` | تعریف شرکت و رد شناسه ملی نادرست/کد تکراری، سال مالی با تقویم شمسی و رد هم‌پوشانی، تعیین سال مالی سند از شرکت انبار و قطعی‌نشدن در سال بسته، مرکز هزینه درختی |
| `product-categories.spec.ts` | گروه کالای درختی، ذخیره گروه/بارکد/شناسه مالیاتی روی کالا، رد شناسه مالیاتی نادرست و بارکد تکراری، حذف‌نشدن گروه دارای کالا |
| `serials.spec.ts` | رسید کالای سریال‌دار از فرم و خطای ناهمخوانی تعداد سریال با مقدار، نمایش سریال در گزارش، رد حواله سریالی که در آن انبار نیست، خروج سریال با حواله و برگشتش با ابطال |

مراحل تأیید و قطعی کردن سند انبار در برنامه از کارتابل گردش کار انجام می‌شوند؛ تست آن‌ها را مستقیم با API انجام می‌دهد.
